## 1. 배경

- 회사는 항만 하역 업체다. 보험료와 항만부지 임차료·사용료를 미리 지급하고, 계약기간에 걸쳐 비용으로 나눈다.
- ERP에서 결산 기준 원자료 엑셀을 매달 내려받는다. 파일 이름은 `선급비용('YY.M).xlsx`이고, 1행이 헤더인 건별 목록이다.
- 원자료에는 결산일자, 발생금액, 시작시간, 종료시간, 계산비율, 발생계산금액 같은 열이 있다. 발생계산금액은 원장에 반영된 잔액이며 음수로 들어 있다.
- 지금까지는 담당자가 월별 비용과 기준일 잔액 명세서를 손으로 만들었다. 원장 잔액과 맞는지 확인하는 데 시간이 걸린다.

## 2. 목표

| # | 목표 | 성공 기준 |
|---|---|---|
| G1 | 원자료만 넣으면 월별 비용과 월말 잔액 명세서가 자동으로 나온다 | 명령 한 번 또는 "N월 명세서 만들어줘" 요청 한 번 |
| G2 | 기준일 잔액이 원장과 맞는다 | 건별로 원장 발생계산금액과 **1원 단위까지 일치**(차이 0) |
| G3 | 결과가 숫자를 붙여 넣은 표가 아니라 수식으로 된 Excel이다 | 원자료나 기준일을 바꾸면 Excel에서 다시 계산됨 |
| G4 | 월별 결과물을 따로 보관하고, 원본은 건드리지 않는다 | `선급비용명세서('YY.M).xlsx`가 새로 만들어지고 원자료 파일은 바뀌지 않음 |
| G5 | 다음 달에도 같은 방식으로 반복할 수 있다 | Claude Code 스킬 `prepaid-expense-schedule`로 재사용 |

## 3. 범위

**포함**
- 건별·계정과목별 월별 발생 비용(상각액)
- 기준일까지의 비용 누계와 기준일 선급비용 잔액
- 건별·계정과목별 월말 선급비용 잔액
- 원장 대사: 각 행의 결산일자 기준으로 잔액을 다시 계산해 발생계산금액과 비교
- 대상 계정은 현재 하역관리비(항만시설사용료, 5501)와 보험료(6121)다. 원자료에 다른 계정이 들어오면 자동으로 포함된다.

**제외 (요청받지 않음)**
- ERP 전표 생성이나 업로드
- 장기선급비용(장기여부=Y)을 따로 분류하는 기능. 현재 데이터는 모두 N이다.
- 외화 환산 재평가. 원화금액을 기준으로 계산한다.

## 4. 이해관계자

- **결산 담당자(요청자):** 매달 명세서를 만들고 원장과 대사한다. 숫자가 원장과 1원 단위로 맞는 것을 가장 중요하게 본다.
- **검토자(팀장/회계):** 명세서를 확인한다. 계정과목별 요약을 사용한다.

## 5. 업무 규칙 (원장과 맞추며 확인한 것, 바꾸지 말 것)

1. 기간은 **분 단위**로 계산한다. 원자료의 시작시간과 종료시간을 그대로 쓴다.
   - 처음에는 일 단위로 계산했는데, 275일 계약 1건에서 원장과 1,062원 차이가 났다. 그래서 분 단위로 바꿨다.
2. 기준시점은 **기준일 24:00**이다.
3. 잔여비율은 **소수 5자리에서 반올림**한 뒤 금액에 곱한다. 원장도 같은 방식이다.
4. 잔액은 원 단위에서 반올림한다. 월별 비용은 전월말 잔액에서 당월말 잔액을 뺀 금액이다. 그래서 건별 비용을 모두 더하면 발생금액과 같다.
5. 월말 잔액 표에서 **회계일자(지급) 전인 달의 잔액은 0**이다. 사용자 요청으로 표를 추가한 뒤 이렇게 정했다. 그 전에는 아직 지급하지 않은 건이 잔액에 잡혀 2025년 11월 잔액이 12억으로 나왔다.
6. 원장 대사는 **각 행의 결산일자 기준**으로 한다. 원자료에는 1·3·4·6월 결산에서 넘어온 행이 섞여 있고, 그 행의 발생계산금액은 그 결산일 시점의 잔액이다.

## 6. 제약과 가정

- 환경은 Windows 11, Python 3.15, openpyxl이다.
- **이 PC에서는 Excel COM 자동화가 안 된다**(TYPE_E_CANTLOADLIBRARY). **LibreOffice 재계산도 안 된다**(AF_UNIX 오류).
  - 그래서 수식 결과는 Python으로 같은 계산을 따로 해서 검증한다.
  - 사용자에게는 Excel에서 처음 열 때 숫자를 확인해 달라고 안내한다.
- openpyxl로 저장하면 x14 데이터유효성(장기여부 Y/N 드롭다운)이 사라진다. 스크립트가 다시 넣는다.
- 원자료에서 날짜 열은 텍스트(`yyyymmddhhmm`)와 Excel 날짜값이 섞여 있다. 이전 결산에서 넘어온 행은 날짜값이다.

## 8. 미결 사항과 위험

- **10월 원자료가 9월과 완전히 같다.** 23건이고, 결산일자는 9/30까지만 있으며, 10월 신규 건이 없다. 실제 10월 결산 자료가 따로 있는지 사용자에게 확인해야 한다.
- **원자료 오타:** 5행 적요에 "2022026년"이 있다. 원자료는 고치지 않았다.
- **Excel 확인 전:** 사용자가 Excel에서 결과 파일을 열어 숫자를 확인했는지 아직 모른다.
- **남은 파일:** 폴더의 `선급비용명세서.xlsx`는 이전 이름으로 만든 파일이다. 지울지 사용자에게 물었지만 답을 받지 못했다.
- `선급비용('26.9).xlsx`에는 초기 작업 때 넣은 '명세서' 시트가 원본 파일 안에 남아 있다. 이후 방침은 원본을 고치지 않는 것이다.
